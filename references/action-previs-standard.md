# Action Previs Standard

这是 `blender-whitebox-previs` 中涉及实际动作、接触和受力的强制标准。纯构图、机位测试或无交互的站位镜头按主技能的 composition/staging 分支执行，无需强套接触链。它用于把叙事中的动作变成可播放、可检查、可交接的 Blender 白膜预演。白膜的职责是证明空间、顺序、接触、受力、遮挡、时间和运镜能够成立；它不是最终材质、最终灯光、最终特效，也不是“摆几个方块给模型猜”。

## 1. 为什么会出现“两个方块慢慢变大”

这种结果通常来自四个错误：没有先写动作因果，只给了角色和镜头；把物体缩放或滑动误当成运动；相机先动导致动作被遮住；没有检查接触帧和结果帧。修复顺序固定为：动作契约 → 空间路线 → 姿态与接触 → 受力和结果 → 中性机位审查 → 生产运镜。任何一步缺失都只能标记 `DRAFT` 或 `REVIEW`。

## 2. Action contract

每个涉及物理交互的生成单元先写一张 action contract，再建模；纯构图单元改用主技能中的构图目标与首尾状态：

```text
unit_id:
duration / fps / frame_range:
story_verb: 一个主物理动词，例如 dive, catch, brace, pull, break, land, turn, carry
state_in: 每个角色的姿态、受伤状态、道具归属、威胁位置、门/墙/平台状态
trigger: 什么事件迫使动作开始
preparation: 蓄力、转身、屈膝、展开翅根、伸手或寻找支点
contact: 哪只手/脚/身体部位与哪个目标接触，接触发生在哪一帧
reaction: 接触后的重量转移、反冲、失衡、门体/怪物/道具的反应
state_out: 最终位置、朝向、姿态、伤势、道具归属、屏幕方向和环境损坏状态
camera_promise: 相机必须让观众看清的一个事实
known_limits:
status: DRAFT | REVIEW | READY_FOR_PROMPT
```

动作必须能从 `state_in` 推导到 `state_out`。如果故事只写“角色A飞过去救角色B”，白膜仍要补足俯身起飞、飞行路线、落点、抓取/捏碎的接触和怪物结果；不能让模型自行补全。

## 3. 空间 block map

先做俯视图，再做立面/高度图。每个地图至少标出：

- `A0` 起点、`A1` 准备点、`A2` 接触点、`A3` 反应点、`A4` 退出点；
- threat lane、safe lane、action axis、eyeline、碰撞边界和出口；
- 门、墙、栏杆、平台、楼层高差、坠落区、绳索、关键道具的真实近似尺寸；
- 相机初始位置、验证位置和生产路径。

角色路线用曲线或节点表达，不能只靠关键帧让物体从 A 点跳到 B 点。人物从高处下坠、飞行或冲刺时必须在立面图中显示高度变化和落点，不能用平面滑动伪装。

## 4. 代理层级与语义颜色

环境使用中性灰、无纹理、无装饰的体块；用真实近似尺寸保留会改变阻挡、遮挡、接触和高度判断的几何。角色采用稳定语义色，颜色只作身份标识：

```text
yellow = CHARACTER_A
pink   = CHARACTER_B
red    = THREAT / CREATURE
cyan   = CRITICAL_PROP
blue   = CAMERA / SAFE_MARKER
```

根据动作精度选择代理：

1. `Level A layout/camera`：立方体、胶囊、圆柱或简单轮廓，用于位置、间距、占位、群体分布、遮挡、构图和镜头通行；保持真实近似身高与宽度，必要时加朝向标记。此层只证明布局，不证明步态与人物表演。
2. `Level B pose`：有头、躯干、上/下臂、手、上/下腿和脚，用于蹲伏、瞄准、伸手、支撑和转向。
3. `Level C contact`：带明确关节、手掌/脚掌 socket、翼根、武器/道具 socket 的代理，用于抓取、救援、摔落、打击、绳索受力和机构操作。

同一镜头可混合灰色环境简模、前景B级人形、远景A级占位和局部C级接触。越肩构图或人物轮廓决定画面时，即使不打斗也用B级；只有站位和远近关系时不必给每个人加完整骨架。凡是手、肩、膝、脚、翼根或接触点决定含义的镜头，禁止用不可辨认的立方体或圆柱体代替。人物、门、怪物和道具必须各自有独立对象和清晰层级，禁止把两个角色合并成一块几何。

## 5. 中性验证相机下先完成动作

先用固定、足够高且无遮挡的 neutral verification camera 检查动作，不追求电影构图。验证相机要同时看见起点、接触区和结果区；必要时使用一个俯视机位和一个立面机位分别检查平面路线与高度路线。

涉及动作接触的镜头按已确定剧情呈现相关链条（纯构图不适用）：

```text
occupied first frame
→ trigger
→ preparation
→ travel / approach
→ contact or obstruction
→ reaction / weight transfer
→ visible result
→ clean exit handle
```

身体姿态要解释力的方向：

- 俯冲/飞行：躯干前倾，头胸朝运动方向，腿和翅膀跟随惯性，落点前有减速或制动；禁止直立人形平移。
- 下坠：身体先失去支撑，再按重力方向下降，手脚可寻找支点；禁止“站在空中向下移动”。
- 冲刺/跳跃：先有屈膝和重心转移，再离地，落地后有屈膝吸收冲击；禁止瞬移或缩放。
- 救援/扶持：必须看见救援者到达、抓住/托住被救者、重量转移和被救者姿态变化；救援者不能穿过对方或隔空移动对方。
- 打击/捏碎：攻击部位先接近并接触目标，目标产生受力位移、破坏或倒地结果；禁止只让攻击者挥动而目标自动消失。

门、墙、栏杆、绳索和平台同样要有接触与间隙。任何物体穿过实体、在未接触时移动、或从遮挡后凭空出现，都必须退回动作层修正。

## 6. 时间与关键帧审查

按目标 fps 明确 frame range，至少保存以下审查帧：

- `F0`：第一帧已经有主体和状态，或明确写出 reveal 机制；
- `F_trigger`：触发动作的事件；
- `F_prepare`：蓄力/转身/屈膝/伸手等准备姿态；
- `F_contact`：手、脚、身体、翼根或道具真正接触；
- `F_reaction`：重量、反冲、阻挡物或怪物的响应；
- `F_result`：观众能确认目标已经被救、击退、破坏、打开或逃出；
- `F_exit`：连续镜头或下一片段可以继承的干净尾状态。

身体不能在接触前先反应，物体不能在手/力到达前先移动，道具不能跳变归属。每个镜头至少渲染首帧、中帧、尾帧和所有关键接触帧；将“动作路线图”和“关键帧审查图”与 `.blend` 一起保存。

## 7. 运镜后置

对动作镜头，先声明构图目标，动作通过中性机位后再细化生产相机。纯构图镜头允许先设计机位和镜头再调整占位，不必凭空增加肢体动作。相机表至少写清：起点高度、目标点、路径、镜头/FOV、接触时的取景、结尾取景、屏幕方向和与下一段的继承关系。

相机的职责是揭示动作、接触和结果：

- 可以跟随、推进、拉远、俯视、绕到结果侧，但每次移动都要有叙事理由；
- 一个镜头保持一个主要轴和一个主要动作，跨轴必须有可见的重置或明确的揭示目的；
- 镜头不能用缩放、装饰性环绕或遮挡来替代缺失的动作；
- 不要非预期卡顿、随机变焦、突然传送、无理由穿越动作轴或在关键接触时把主体移出画面；有意的固定机位和静态构图不属于失败；
- 先批准相机位置和目标路径，再加入低频、克制的手持漂移。

## 8. 反快捷方式拒绝清单

以下任一项出现，状态只能是 `DRAFT` / `REVIEW`，不得标记 `READY_FOR_PROMPT`：

1. 声称表现人物救援/战斗/表演，却只有两个方块缩放、平移或穿插；纯构图/占位镜头合理使用简模不在此拒绝项内。
2. 人物站着飞、站着下坠，或没有蓄力/落地/减速姿态。
3. 角色穿过门板、墙体、怪物或另一个角色。
4. 救援缺少抓取、托举、重量转移和被救者反应。
5. 打击/捏碎缺少接触点，目标却自动消失或提前倒下。
6. 道具、绳索、门体或车辆在力到达前移动，或凭空改变归属。
7. 相机移动很复杂，但观众仍看不懂谁动了、为什么动、碰到了什么、结果是什么。
8. 仅有装饰性建筑，无法判断高度、路线、出口、遮挡或碰撞。
9. 各生成片段用不同坐标重建，导致位置、朝向、伤势、道具状态或屏幕方向断裂。
10. 只给 `.blend` 或静态截图，没有可播放白膜视频和关键接触审查证据。

## 9. 交付与交接模板

```text
WHITEBOX HANDOFF
project / unit_id / version:
duration / fps / resolution / aspect_ratio:
status: DRAFT | REVIEW | READY_FOR_PROMPT
blend_file:
whitebox_render:
mode: action | mixed
proxy_levels: object -> A / B / C and reason
audit_frames: F0, F_prepare, F_contact, F_reaction, F_result, F_exit (only applicable events)
route_map:
action_sheet:

semantic_legend:
- yellow / CHARACTER_A -> character reference N
- pink / CHARACTER_B -> character reference N
- red / THREAT -> creature reference N
- cyan / CRITICAL_PROP -> prop reference N

state_in:
state_out:
story_verb:
trigger:
route_nodes:
contact_and_force:
camera_path:
screen_direction:
continuity_to_next_unit:
known_limits:
```

白膜视频负责位置、路线、顺序、遮挡、接触、时间和相机；角色图、环境图、怪物图和道具图负责外观；文字提示词负责表演、物理约束、光效、声音和可见结尾。若白膜与提示词冲突，先修正并重新审查白膜，不能让生成模型自行选择另一套路线。

## 10. 白膜的边界

白膜不证明最终材质、皮肤、羽毛、血液、烟尘、破坏特效、灯光审美或最终生成模型的稳定性。它证明的是动作和空间是否成立，并为后续视频提示词提供可复制的路线、姿态、时间和镜头依据。只有完成动作审查、连续性审查和交接资料，才能进入 `READY_FOR_PROMPT`；“看起来像电影”不能替代动作证据。
